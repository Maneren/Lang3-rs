# Architectural Solution: Handling Invariants and Eliminating Expect/Unwrap Spam

## Overview & Objectives

In the current VM and Compiler implementation, many compiler-maintained structural invariants are expressed at runtime through scattered calls to `.expect(...)`, `.unwrap()`, or dynamic runtime error checks (e.g. `RuntimeError::generic("stack underflow")`).

Since the VM operates on compiler-generated bytecode assumed to be well-formed, these checks pollute the execution loop and create boilerplate.

The objective of this architecture is to **explain structural invariants to Rust's type system and VM abstractions** using type-level wrapper types, encapsulated domain models, and standard language features (like `Index` traits) — without using `unsafe` or overhead-heavy bytecode verification.

---

## Architectural Pillars

### 1. Strongly Typed Domain Handles (Newtypes)

Instead of using primitive `usize` types in instruction fields, domain handles are defined in `l3_bytecode`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct ConstantIndex(pub u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct LocalIndex(pub u16);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct UpvalueIndex(pub u16);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct ChunkId(pub u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct CodeOffset(pub u32);
```

#### Updated `Instruction` Enum
Instruction payloads use these handles directly:
- `Constant { index: ConstantIndex }`
- `GetGlobal { name_index: ConstantIndex }` / `SetGlobal { name_index: ConstantIndex }`
- `GetLocal { index: LocalIndex }` / `SetLocal { index: LocalIndex }`
- `GetUpvalue { index: UpvalueIndex }` / `SetUpvalue { index: UpvalueIndex }`
- `Closure { function_index: ConstantIndex, upvalues: Vec<UpvalueDesc> }`
- `Jump { offset: CodeOffset }` / `JumpIf { offset: CodeOffset, ... }`
- `ForLoop { control_index: LocalIndex, limit_index: LocalIndex, body_offset: CodeOffset, inclusive: bool, step_index: Option<LocalIndex> }`

### 2. Unified `ConstantPool` with Encapsulated Type Accessors (Option B)

`ProgramBytecode` stores constants in a `ConstantPool` wrapper type.

```rust
#[derive(Debug, Clone, Default)]
pub struct ConstantPool {
    constants: Vec<HeapCell>,
}

impl ConstantPool {
    pub fn new(constants: Vec<HeapCell>) -> Self {
        Self { constants }
    }

    pub fn get(&self, idx: ConstantIndex) -> &HeapCell {
        &self.constants[idx.0 as usize]
    }

    /// Invariant: Compiler emits a valid string constant index for global names.
    pub fn string(&self, idx: ConstantIndex) -> &str {
        self.get(idx)
            .value
            .as_string()
            .expect("compiler invariant: constant at index is String")
    }

    /// Invariant: Compiler emits a valid bytecode function constant index for closures.
    pub fn bytecode_function(&self, idx: ConstantIndex) -> &BytecodeFunction {
        match &self.get(idx).value {
            HeapData::Function(Function::Bytecode(bc)) => bc,
            _ => unreachable!("compiler invariant: constant at index is BytecodeFunction"),
        }
    }
}

impl std::ops::Index<ConstantIndex> for ConstantPool {
    type Output = HeapCell;

    fn index(&self, idx: ConstantIndex) -> &Self::Output {
        self.get(idx)
    }
}
```

This encapsulates all expectation logic inside `ConstantPool` type accessors (`pool.string(idx)` and `pool.bytecode_function(idx)`), leaving the VM instruction handlers clean and free of assertion spam.

### 3. Encapsulated VM Stack (`VmStack`)

`self.stack` is converted from `Vec<StackValue>` to a dedicated `VmStack` struct:

```rust
pub struct VmStack {
    values: Vec<StackValue>,
}

impl VmStack {
    pub fn new() -> Self {
        Self { values: Vec::new() }
    }

    pub fn push(&mut self, val: StackValue) {
        self.values.push(val);
    }

    /// Pops top value assuming valid bytecode stack height.
    pub fn pop(&mut self) -> StackValue {
        self.values.pop().expect("compiler invariant: stack non-empty")
    }

    /// Pops two values in evaluated order: (lhs, rhs).
    pub fn pop2(&mut self) -> (StackValue, StackValue) {
        let rhs = self.pop();
        let lhs = self.pop();
        (lhs, rhs)
    }

    pub fn top(&self) -> StackValue {
        *self.values.last().expect("compiler invariant: stack non-empty")
    }

    pub fn top_mut(&mut self) -> &mut StackValue {
        self.values.last_mut().expect("compiler invariant: stack non-empty")
    }

    pub fn get_local(&self, fp: usize, index: LocalIndex) -> StackValue {
        self.values[fp + index.0 as usize]
    }

    pub fn set_local(&mut self, fp: usize, index: LocalIndex, val: StackValue) {
        self.values[fp + index.0 as usize] = val;
    }

    pub fn peek_from_top(&self, depth: usize) -> StackValue {
        let idx = self.values.len() - depth - 1;
        self.values[idx]
    }

    pub fn truncate(&mut self, len: usize) {
        self.values.truncate(len);
    }

    pub fn len(&self) -> usize {
        self.values.len()
    }

    pub fn drain_top(&mut self, count: usize) -> impl Iterator<Item = StackValue> + '_ {
        let start = self.values.len() - count;
        self.values.drain(start..)
    }
}
```

#### Benefits
- Eliminates `Self::pop_value(&mut self.stack)` and `Self::top_value` helper routines.
- Operations like `Instruction::SetLocal` simplify to:
  `self.stack.set_local(fp, index, val);`
- Binary and binary-comparison operations use `self.stack.pop2()`.

### 4. `CallStack` Abstraction and Step Control Flow

Frame management in `BytecodeVM` is wrapped in a `CallStack` structure:

```rust
pub struct CallStack {
    frames: Vec<CallFrame>,
}

impl CallStack {
    pub fn current(&self) -> &CallFrame {
        self.frames.last().expect("active frame exists")
    }

    pub fn current_mut(&mut self) -> &mut CallFrame {
        self.frames.last_mut().expect("active frame exists")
    }

    pub fn push(&mut self, frame: CallFrame) {
        self.frames.push(frame);
    }

    pub fn pop(&mut self) -> CallFrame {
        self.frames.pop().expect("active frame exists")
    }

    pub fn is_empty(&self) -> bool {
        self.frames.is_empty()
    }
}
```

### 5. Native `Index` Trait Implementations

For collections in `ProgramBytecode` and `Chunk`:

```rust
impl std::ops::Index<ChunkId> for ProgramBytecode {
    type Output = Chunk;

    fn index(&self, id: ChunkId) -> &Self::Output {
        &self.chunks[id.0 as usize]
    }
}

impl std::ops::Index<CodeOffset> for Chunk {
    type Output = Instruction;

    fn index(&self, offset: CodeOffset) -> &Self::Output {
        &self.code[offset.0 as usize]
    }
}
```

Indexing syntax `program[chunk_id]` and `chunk[ip]` uses Rust's built-in bounds checking without `.get(...).expect(...)` string overhead.

## Crate Refactoring Sequence

1. **`l3_bytecode`**:
   - Define handle newtypes (`ConstantIndex`, `LocalIndex`, `UpvalueIndex`, `ChunkId`, `CodeOffset`).
   - Add `ConstantPool` struct and `Index` implementations for `ProgramBytecode` and `Chunk`.
   - Update `Instruction` enum definitions and formatters/optimizers.

2. **`l3_compiler`**:
   - Update code emission routines to construct strongly typed indices (`ConstantIndex`, `LocalIndex`, etc.).

3. **`l3_vm`**:
   - Integrate `VmStack` and `CallStack`.
   - Refactor `execute_loop` instruction dispatch to use `VmStack`, `ConstantPool` accessors, and handle indexing.

4. **Verification**:
   - Run `cargo test` and verify all unit and snapshot tests pass without regression.
